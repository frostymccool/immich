People

Each person has their own Immich account (API key) and their own folder(s). A file goes to the person whose folder it is in; for files in the shared area, the copyparty login of whoever uploaded it decides. Nothing is ever deleted in Immich or on disk from here.

Folders nobody imports

When you remove a person, their folders land here so their files do not quietly flow into the main account. Give a folder back to the main account to import it again.

Add a person

Create their Immich account first and an API key inside it (Account Settings > API Keys, “all permissions” is simplest). They start paused so you can look first; then press Review & start.

Add by hand instead (name, folders, copyparty login)

Add already-imported files to albums

One-off: puts files imported before folder albums were switched on (or while the Immich key lacked album permissions) into the album named after their folder, creating albums that don't exist yet. Nothing is uploaded again and nothing is deleted. Safe to run again.

Re-import everything

Makes the bridge forget what it has imported and import every file in the watched folders again, into the Immich account the API key belongs to now (see the Status tab). Use it after switching the API key to a different Immich account. Nothing on the NAS or already in Immich is changed or deleted; files Immich already has in that account are simply recognised as duplicates. It uploads everything again over your network, so it can take a long time.

Set by the installer (read-only here)

The port, Immich address and API key live in docker-compose.override.yml / immich-bridge.env on the VM. To change the port, re-run the installer with BRIDGE_PORT=9000 in front. A container cannot safely rewrite its own port mapping or mounts.
